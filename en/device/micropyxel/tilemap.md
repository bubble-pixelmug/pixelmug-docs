# Tilemaps

Tilemap saves "Each cell displays which 8x8 block of the image library " , which is suitable to repeat the background or the larger scene. It stores the plot coordinates, not RGB or pixel colours.

## Current limitations

Studio does not currently provide a visual Tilemap editor. Small maps or a layout generated by a program can be created using an interface such as `set()`, `pset()`; more complex maps can be produced using a stand-alone open source tool [Tiled Map Editor](https://www.mapeditor.org/), and then by `Tilemap.from_tmx()` loading the exported TMX file.

MicroPyxel's diagrams are fixed to `8×8` pixels. The TMX file only describes which of the blocks is used in each cell of the map, and does not automatically load Tileset pictures; the program still needs to load the corresponding PNG material to Image and let Tilemap quote the Image.

The current TMX loader only supports a limited subset of Tild format. Maps should be made using the active Tile Layer, embedded Tileset and CSV codes to avoid external TSX, Base64 or compressing data, multiple Tileset, object layers, unlimited maps and block flipping. The full range is [TMX Range](#tmx-范围) at the end of this paper.

`bltm()` only draws created or loaded Tilemap to the screen without relying on a specific editor.

## Tile values and coordinate units

The current component is presented in an integer: ** Low 8 bits is u and High 8 bits is v**. `u,v` is the column, row, not pixel coordinates of the image library.

```python
tile = (v << 8) | u
u = tile & 0xFF
v = (tile >> 8) & 0xFF
```

The initial 256x256 Gallery can accommodate 32x32 8x8 blocks, so the actual source block coordinates are usually `u,v=0..31`.

| Operation | Coordinate Unit |
| --- | --- |
| `width/height`, `pset`, graphics, `blt` | Number of blocks |
| Screen/image `bltm` | pixels, including source `u,v,w,h` |

## Load and create

| Interface | To fill parameters and return values |
| --- | --- |
| `tilemaps(index)` | To fill in the integer number, currently only 0; return global Tilemap |
| `Tilemap(width,height,img)` | Three mandatory, the first two being the number of blocks in positive integers; `img` being indexed to the Gallery or Image; returning independent Tilemap |
| `Tilemap.from_tmx(filename,layer)` | Two mandatory, device file path and layer number from 0; return to stand-alone Tilemap, failed `OSError` |

All above are position parameters. Prefer to `tilemaps(0)`; for independent objects, the original memory release limit is [Overview](./).

## Draw maps with `bltm`

```text
pyxel.bltm(x,y,tm,u,v,w,h,colkey=None,rotate=None,scale=None)
```

The first seven must be filled, only at parameter. Top floor `tm` It's a map library index, currently only zero.`colkey` It's about jumping.**Pixels Index**, not a block value;default `None`.`rotate=None` Equivalent 0 degrees, clockwise;`scale=None` Equivalent 1, use positive. `w/h` Flip separately.

```python
import time
import micropyxel as pyxel

pyxel.init()
try:
    image = pyxel.images(0)
    image.rect(0, 0, 8, 8, 8)   # Blocks (0,0)
    image.rect(8, 0, 8, 8, 10)  # Blocks (1,0)
    tm = pyxel.tilemaps(0)
    tm.pset(0, 0, 0)           # u=0, v=0
    tm.pset(1, 0, 1)           # u=1, v=0
    tm.pset(0, 1, 1)
    tm.pset(1, 1, 0)
    pyxel.cls(0)
    pyxel.bltm(8, 0, 0, 0, 0, 16, 16)
    pyxel.render_graphics()
    time.sleep_ms(3000)
finally:
    pyxel.destroy()
```

Rotates/scales maps with the engine creating `abs(w)×abs(h)` pixels for temporary Image, and then transforms them. Draws only the desired view, and does not change the entire map for the 32x16 screen.

The current normal drawing path `bltm` uses the index in the image of the block, then the target map is used instead of the complete RGB merge path `blt`. Map materials prefer the default palette that is consistent, and do not assume that maps with custom PNG palettes are fully consistent with `blt` visible.

## Tilemap methods

All parameters are position parameters. The parameters in the table below that do not indicate the default value are filled.

| Methodology | Roles and Return Values |
| --- | --- |
| `width()`, `height()` | Returns number of block columns, lines |
| `imgsrc()` | Returns the image library integer index or Image package; can be `None` if no active image |
| `set_imgsrc(value)` | Gallery Index or Image;`None` Reset to Gallery 0, not untie |
| `data_ptr()` | Returns the whole number of the bottom block buffer address or `None`, usually without use |
| `set(x,y,data)` | Integer block position, equal string list/tuple, as shown below |
| `clip(x,y,w,h)` / `clip()` | Block coordinates cropped or restored without reference |
| `camera(x,y)` / `camera()` | Block Coordinate Offset, or Unparticipated Restore |
| `cls(tile)` | Full Image Fills Same Block |
| `pget(x,y)` | Returns packaged whole number of blocks |
| `pset(x,y,tile)` | Set a block |
| `line(x1,y1,x2,y2,tile)` | Draw lines with the same drawing block |
| `rect(x,y,w,h,tile)`, `rectb(x,y,w,h,tile)` | Chart Rectangle & Borders |
| `circ(x,y,r,tile)`, `circb(x,y,r,tile)` | Circles and Borders |
| `elli(x,y,w,h,tile)`, `ellib(x,y,w,h,tile)` | Ellipse & Borders |
| `tri(x1,y1,x2,y2,x3,y3,tile)`, `trib(x1,y1,x2,y2,x3,y3,tile)` | Chart Triangle and Borders |
| `fill(x,y,tile)` | Fill the same connected pieces from the torrent point |
| `blt(x,y,tm,u,v,w,h,tilekey=None,rotate=None,scale=None)` | Copying map grids; source can be map library numbers or Tilemap; default opacity, 0 degrees, 1 times |

The setting, drawing and copying operation returns `None`. The transparency parameter `Tilemap.blt()` is a packaged ** block value**, which is different from the colour transparency parameter that shows the interface `bltm()`. It copys the block grid and does not replace the image source.

### `set()` string order different from integer order

Each block is represented by four hexadecimal characters `uuvv`. For example, a string `"0100"` indicates `(u=1,v=0)`, while `pset()` corresponds to `0x0001`, not `0x0100`.

```python
tm = pyxel.tilemaps(0)
tm.set(0, 0, ["00000100", "01000000"])
print(tm.pget(1, 0))  # 1
```

Lines should be equal in length and equal to four times, and can be separated by blanks. The current illegal line does not leave the anomaly in uniform, and the material format should be pre-established.

## Supported TMX subset

The current loader supports a limited subset of Tiled style TMX:

- The size of the block must be 8x8.
- Layer data is coded with CSV, and Base64 compressed data is not supported.
- Reads the first tileset, requires an embedded definition and contains `columns` and does not support a common import that relies on external TSX.
- Do not automatically read or load pictures of tileset, and apply the self-prepared library.
- Do not provide full Tiled flip sign, multiple tileset, object layer or unlimited map support; do not produce material for full TMX compatibility.
- The current empty GID is map to `(0,0)` with the first image; the block is created as empty if space is needed.

When a stand-alone map is loaded, the required area can be copied into the global map library, using the top layer `bltm`:

```python
source = pyxel.Tilemap.from_tmx("map.tmx", 0)
pyxel.tilemaps(0).blt(0, 0, source, 0, 0, 4, 2)
pyxel.bltm(0, 0, 0, 0, 0, 32, 16)
```
