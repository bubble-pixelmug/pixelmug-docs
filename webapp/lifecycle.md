# WebApp 会话与生命周期

一个 `BubbleWebApp` 实例对应一次页面会话。SDK 使用 `sessionId` 标识这个页面实例，让 Bot 能区分同一用户打开的不同页面，并把设备事件或定向推送发送给正确的页面。

## 创建页面会话

通常只需要创建实例：

```js
const webapp = new BubbleWebApp({ ble: false });
```

构造函数默认会自动调用 `start()`。这里的“启动”不是启动网页、服务器或 Bot，而是完成两件事：

1. 通知 Bot 当前页面会话已经打开；
2. 启动页面心跳，持续告诉 Bot 这个会话仍然活跃。

Bot 收到页面打开通知后，会以 `sessionId` 为键记录打开页面的用户、所在对话和最近活动时间。页面订阅设备事件时，订阅关系也会保存在这条会话记录中。Bot 随后可以根据这些信息，把设备事件和设备关联变化（比如用户切换了关联的设备）转发给正确的页面。

正常业务不需要手动调用 `start()`。只有应用需要自行控制页面会话从何时开始时，才设置 `autoStart: false`，并在页面准备好后调用：

```js
const webapp = new BubbleWebApp({
  ble: false,
  autoStart: false,
});

// 完成应用自己的初始化后，再开始页面会话。
webapp.start();
```

如果没有明确的启动时机要求，保持默认行为即可。

## `sessionId` 标识什么

`sessionId` 标识一次正在运行的页面实例，不代表用户、对话或页面 URL。重新打开或刷新页面会创建新的 `BubbleWebApp` 实例，也会产生新的 `sessionId`。

WebApp 发出的请求会携带当前 `sessionId`。Bot 返回定向数据时也带上这个标识；页面收到属于其他会话的数据会将其忽略。这样，即使同一个用户在一段时间内存在多个页面会话，每个页面也只处理发给自己的数据。

关于定向推送和多个页面会话，见 [Bot 主动向 WebApp 推送](./push)。

## 心跳与会话过期

页面会话启动后，SDK 默认每 25 秒发送一次心跳。Bot 收到心跳后更新该会话的最近活动时间，不会把心跳交给业务处理器。

Bot 侧的页面会话默认有效期为 90 秒。如果页面异常退出、网络中断或关闭通知没有送达，Bot 在持续收不到心跳后会清理过期会话，停止向它转发设备事件和设备关联变化。

这些时间由 SDK 自动管理，普通应用不需要调整。

## 页面关闭与 `stop()`

页面正常退出时，SDK 会自动停止心跳并通知 Bot 会话已经关闭。Bot 收到后会删除对应的会话记录，因此普通页面不需要主动调用 `stop()`。

如果单页应用在页面本身没有关闭的情况下卸载 WebApp 功能，可以手动结束会话：

```js
webapp.stop();
```

`stop()` 表示这个页面会话不再活跃，并停止后续心跳。它用于结束会话状态，不是通用的页面销毁接口。

## Bot 会话与业务记录

Bot SDK 维护的页面会话主要服务于生命周期、设备事件订阅和设备关联变化转发。如果业务代码为了稍后主动推送而自行保存了 `sessions` 表，仍需要由业务代码设置过期时间并清理记录；SDK 不会自动管理这份业务数据。
