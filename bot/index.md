# Bot SDK

冒泡 App 是用户与设备交互的入口，以对话（Chat）作为主要交互方式。用户可以像聊天一样发送消息、点击按钮、接收设备状态，也可以打开 WebApp，通过图形界面完成更复杂的操作。开发者可以先用消息和按钮实现基本功能，再按需要补充页面交互。

群组让这种交互从个人控制设备扩展到多人、多设备协作：不同用户可以在同一个群组中与 Bot 交互，Bot 根据业务逻辑调用关联设备，并将执行结果或设备事件反馈到对话中。例如，家庭成员可以共同操作家中的设备，团队也可以通过一个 Bot 协调多台设备完成任务。这样，应用可以围绕群组中的成员、设备和协作流程来组织，而不局限于“一个人通过一个控制页面操作一台设备”。具体的业务场景通过开发 Bot 实现。

Bot 把冒泡对话与业务逻辑连接起来：接收用户消息、发送文字和媒体、显示操作按钮，也可以关联 PixelMug 并调用设备能力。Bot 运行在电脑或服务器的 Node.js 中，可由 Studio 启动，也可以独立运行。

第一次开发，先完成[第一个 Bot](./quick-start)，再加入[消息内按钮](./inline-keyboard)和[设备关联](./devices)。

## 应用由哪些部分组成

用户在冒泡 App 中发消息，云端将消息更新交给 Bot。SDK 负责轮询、生成上下文和调用处理器，你在处理器中编写“收到什么、做什么、回复什么”。

```text
冒泡对话 → 云端 → Bot SDK → 业务处理器
                 ↑             │
                 └── 发送回复 ──┘
```

接入设备后，业务代码先用 JavaScript 设备 RPC SDK 构造指令，再由 Bot 发送。设备执行后，Bot SDK 将响应匹配到调用，或把设备事件（如按键被按下、电池未充电等）主动上报交给通知处理器。

```text
业务处理器 → 设备 RPC → Bot SDK → 云端 → 关联设备
业务处理器 ← RPC 结果或设备通知 ← Bot SDK ← 云端 ← 关联设备
```

设备 RPC SDK 是运行在 Bot 一侧的 JavaScript 库，封装了设备固件内置能力的远程调用（RPC）接口。开发者通过设备 RPC SDK 构造指令，再由 Bot SDK 发起调用，就能使用屏幕控制、状态查询等能力，无需编写或部署设备端程序。实际操作由设备固件执行。

[设备端接口](/device/)用于另一类开发：编写直接运行在设备上的程序，实现自定义绘图、交互和传感器处理等逻辑。需要扩展设备本地行为时，再使用这些接口。

## 示例约定

教程使用 `@jeejio-bubble/bot/sdk`，设备示例以 PixelMug S1 为主。先按[快速开始](./quick-start)创建 `bot`，再添加各页的短片段；除明确说明外，处理器应在启动前注册。设备功能使用 `await bot.start()`，同时开启消息和设备轮询。
